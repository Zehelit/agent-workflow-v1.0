# Selective current context (N06)

`tools/render-active-run.py` reads a disposable or explicitly selected project in both the source and installed skill. It never activates, refreshes, migrates or writes workflow state. Supply the actual observation time with `--as-of`; it is not a replacement for source creation or original turn time. Its stable JSON contract is `context_version: 1`. The same state, source, references and observation time yield the same rendering.

The output includes objective and current identity, the exact current authorization or native binding, the original source/goal timestamps, current goal observation, open task contracts and dependency/review pins, execution/acceptance observations, blockers and invalidation counterevidence, changed artifact hashes, evidence file references, and next action. It omits receipt bodies, prepared prompts, full reports, completed final text, transcripts and tool logs. Accepted task contracts stay available in the pinned original state; the compact projection shows their acceptance and exact evidence references.

References are a strict JSON list of `{path, sha256, kind}` objects with optional `task_id`. `kind` is `evidence`, `decision` or `counterevidence`. Paths are exact project-relative safe files; SHA-256 is lowercase and complete. Report bodies stay in their source files. A counterevidence reference remains an explicit blocker until the main makes a deliberate new reference manifest/revision; renderer reduction cannot erase it. Missing or stale hashes, unsupported unpinned context references, absent terminal-result evidence, pending/invalidated dependencies, rejected or uncertain work, and stale goal/inventory/usage are visible blockers. Malformed source state, missing dependencies and malformed pins reject rather than being normalized.

For guarded summary use, pin the reference-manifest JSON itself as an immutable task `file_inputs` item at assignment. `prepare.current_context` has exactly `{path, sha256, manifest_path, manifest_sha256}`. The helper checks that manifest against the task's typed input pin, reads it separately, rerenders from current state and original provenance, and compares the entire summary. A repinned shortened summary cannot remove a blocker or relabel an old quote. Summary observation age is 0..60 seconds. Preparation changes state, so produce a fresh summary before `dispatch-start`, passing the same manifest pin. Omitting this second summary or substituting a manifest rejects. The original helper authorization, usage, native identity, capacity, prepared-argument and revision/hash guards still decide the actual operation. `dispatch_authorized` is always false in a rendering.

Commands that do not opt into `current_context` keep their existing explicit source-reading workflow. Renderer output cannot authorize native tools. Current tool receipts and original human evidence still require main verification; hashes establish byte equality, not provider authentication. Filesystem observations are not an atomic snapshot against arbitrary external writers.

`cache_status` remains `unknown` and `token_measurement` remains `pending_N08`. Selective context is a source contract; it is not a demonstrated native fresh-child reconstruction, cache benefit, token-saving measurement or installed adoption. Use source references to reconstruct the actionable state and retain reviewer counterevidence.

# Execution and acceptance (N07)

`status.task_observations` is a read-only `contract_version: 1` projection over schema2. Each task has its revision, observed execution state/session/time/freshness, independent acceptance state/basis/reviewer identity, and deliberate write ownership. Stale or missing native execution observations become unknown. Native done/idle/stopped frees active execution capacity through the existing fresh inventory calculation; it never accepts artifacts. Pending independent acceptance retains the producer's write claim. The optional open-session cap still counts observed open sessions separately.

A verifier pins the quiescent producer's exact revision/output hashes. A reviewer cannot directly or transitively depend on acceptance of that producer: acceptance dependencies and review observation edges serve different purposes. A producer stays pending while the reviewer runs. Acceptance records the independently accepted verifier in the already-supported task `review` field and checks its distinct session, target revision, input contract and exact output pins. Changing bytes/revision or restoring old bytes after invalidation cannot resurrect an old review. Existing schema2 accepted records without a preserved reviewer link are labeled `historical_unrecorded`, not retrospectively certified independent.

Independence requires both nonempty, distinct native producer/reviewer session identities and matching assigned plus recorded review hashes. The same predicate governs the projection and accepted dependency gates. Incomplete historical acceptance remains readable as `historical_unrecorded`, but cannot release a fresh dependent task at prepare, record or dispatch-start, with or without summary use; its summary includes `DEPENDENCY_NOT_ACCEPTED`. Losing a reviewer link or native identity after prepare also blocks actual dispatch. No historical identity is inferred or silently migrated.

This is an additive projection and use of an existing optional stored field; schema2 is unchanged. Legacy schemas are rejected and cannot be imported. Current authorization and the approved runtime binding stay authoritative; summaries do not activate or replace either.

# Producer handoff gate

`tooling/check-producer.py` is a source-development gate. Run it from a checkout with the bundled Python, `-X utf8 -B`, once normally and once with `-O`. It needs source tests and is intentionally not an installed runtime command. Declare changed paths and the shared API. The fixed selectors reuse core/input/auth/goal/coordination regressions, new context/acceptance adversarial tests, and known A04/A09/A11 counterexamples. A11's historical integration runner is revalidated against the candidate workflow pin in memory for its disposable source-copy fixture; historical runner bytes are preserved and both dependency pins are reported. No broad unchanged monitor/browser suite is implied.

The machine result pins the union of fixed candidate inputs (sources, tests and role definitions) and every declared changed file, including Markdown outside the fixed list. Declared and fixed paths must be existing normalized project-relative files with no traversal, absolute/drive paths, aliases, links or boundary escapes. The entire union is hashed before and after the selected tests; any declared-file drift blocks PASS, and `--expected-pins` must match the complete union. It records selectors/counts/failures and source stability, and always says `independent_acceptance: false`. Red tests, missing selectors, changed pins and invalid rejection metadata block producer PASS. It is a producer check, followed by one independent consequential review after producer termination.

Optional strict rejection metadata has exactly `rejections` and `rework_seconds`; absent metadata means an empty observed rejection list and unknown cost, not fabricated zero cost. Each rejection records defect ID/class, reproduction reference, one corrector identity, focused review identity, revision and exact source pins. A corrector cannot review itself. A second rejection of the same class additionally records a short `root_plan_correction`. The main owns that plan decision and assigns one repair writer and a focused new independent review. No automatic architect/team layer is added.
